# 游戏设计与开发的逻辑地图

设计工作围绕两个互相影响的问题：玩家为什么愿意行动，团队如何把这些行动及其后果稳定做出来。原型、测试与制作会反过来改变最初的想法。下面是便于检验的工作分解，属于本次综合。

```text
玩家与情境 → 体验目标 → 感知、行动和选择
                            ↓
                  规则、状态、信息与内容
                            ↓
                  表现、操作、教学与反馈
                            ↓
                      实际游玩观察
                            ↓
                 修改假设、范围或实现方式

贯穿过程：资源与生产能力、版本与资产、性能与可访问性、交付证据
```

| 设计层 | 真正要回答的问题 | 常见产物 | 何种证据有用 |
|---|---|---|---|
| 体验与人群 | 玩家在什么情境下想做什么、感到什么 | 简表与体验假设 | 行为、表达、原因、继续或退出 |
| 互动与决策 | 玩家获得什么信息，行动为什么值得做 | 交互链、选项与代价 | 理解、取舍、表达和策略迁移 |
| 系统与数值 | 行动如何改变世界，资源怎样流动 | 规则表、状态转换、数值模型 | 边界情况、循环与实际策略 |
| 关卡与教学 | 玩家如何注意到、学会并运用能力 | 情境序列、信息与路径 | 能否在变化情境独立使用 |
| 叙事与内容 | 行动和信息怎样形成理解、情感或故事 | 事实与知情边界、分支条件 | 玩家知道什么、为何相信、实际做什么 |
| 表现与手感 | 输入是否有可靠、可读且合适的回应 | 交互与音画样段 | 误操作、可读性、时序与感受 |
| 制作与工程 | 代表内容能否持续产出并保持一致 | 切片、工具链、资产与状态边界 | 真实工时、返工、运行与恢复 |
| 验证与交付 | 观察支持哪种程度的完成结论 | 试玩记录、构建及设备证据 | 同版本的可复现结果与远端状态 |

选当前最危险的问题进入，不要求依次写完每张表。已经运行的作品，优先依据实际卡点推进；单纯修复一个存档错误时，不要从市场定位重做整款游戏。

## 容易混在一起的概念

- 玩法循环描述玩家反复进行的行为，程序循环组织输入、模拟和绘制；两者有关但不等同。
- 平衡关注选项在具体情境中的价值，既不要求全部数字相同，也不默认削弱一切强力组合。
- 节奏是压力与信息在时间上的安排，难度涉及完成要求、风险与能力；可分别修改。
- 可玩原型检查关键假设，纵向切片检查目标质量与制作流程；切片可小，代表性不能省。
- 正确性、手感、理解与市场表现需要不同观察，不能让一种测试替代所有结论。
- 外部主张、自己的综合、项目结果和个人认可可以互有关联，保存时仍应标清身份。
