# 系统、叙事和 AI 的实现逻辑

以下结构是工程与设计的综合建议，按项目规模选择。没有实时模拟、联网或生成式 AI 的项目无需引入对应系统。

## 状态与裁定

对需要可靠规则的部分，建立可检查的转换。

```text
当前状态 + 已验证的行动 + 显式的随机或外部结果
    → 规则裁定 → 新状态 + 事件记录 → 画面/声音/叙述
```

最小行动规格包括行动者、目标、前置条件、成本、效果、结算顺序、失败结果、重复提交处理，以及哪些内容需要保存。把一次行动变成多个按钮回调时，要保证成本和奖励各结算一次。回合、实时和暂停的时间定义要一致。

不要默认使用复杂架构。小型作品可以只有一个清晰状态对象与少量函数。需要撤销、回放、复杂联机或争议追踪时，再考虑命令或事件记录等结构。逐帧更新是程序组织方式；回合制棋局无需让每个棋子每帧模拟策略。更新顺序可能影响结果，需明确定义。[R02]

存档保存需要恢复的事实，派生显示可重新计算。为稳定对象 ID、版本、深复制可变数据、创建依赖顺序和损坏回退选择适当方案。Godot 官方示例是教学起点，不能据此声称跨版本恢复、嵌套对象和完整游戏状态都已解决。[PROD-02][PROD-03]

## 数值与经济

先列资源从何产生、如何转移、何时消耗、有哪些容量或时间约束，再选公式。明确单位，避免把每回合、每秒和每局混在一起。

用于初步比较的关系可包括：净流量 = 产生量 − 消耗量；期望收益 = 各结果概率与结果值乘积之和；购买回本回合 = 成本 ÷ 每回合新增净收益。它们只是对应假设下的计算，风险、等待、选择权、技能与玩家效用仍需单独分析。不要把随机期望相同写成体验等价。

测试开局、常态和极端状态，检查资源枯竭、无限增长、正反馈滚雪球、负反馈导致无力感、提前锁死和支配策略。竞争玩法关注公平与反制；单人作品可以保留高低差和强力组合，按预期体验决定是否调整。[D03][D04]

## 叙事逻辑与内容生产

分别维护世界事实、角色所知或所信、玩家获得的信息和系统已验证的条件。侦探作品尤其要区分事实、证词、推测和可提交证据。人物撒谎属于故事行为；系统把假证词当真相属于另一类问题。

分支设计写出入口条件、具体内容、变化、汇合条件与结局可达性。后果可以体现为表达、理解、关系或持久状态，按作品承诺决定是否保存。分支汇合可以控制制作量，但不能抹去前面承诺保留的重要后果。ink 的变量、条件、分流与汇合是可参考的表达工具，不要求所有项目使用 ink。[R01]

空间叙事可以让玩家通过物件、路径和事件了解故事；关键事实需要考虑遗漏补救，不能假定玩家必经每个单一信息点。[D06] 估算内容成本时同时计算编写、实现、资产、翻译、回归与更新。少量高影响分支和复用情境是一种办法；单线强作者作品也可以成立。

## 何时让生成式 AI 参与

先说明它带来什么可验证的增量：自然语言行动、角色回应、个性化内容、生成工具或别的能力。分别考虑制作阶段使用 AI 与玩家游玩时调用 AI，后者新增延迟、费用和失败路径。

对于有固定规则、权威真相或经济结算的项目，可以采用：自然语言意图 → 结构化候选行动 → 合法性、权限与上下文校验 → 状态提交 → 据结果生成表达。开放即兴作品可允许生成新事实，也要定义它从何时生效、谁能修改、如何回忆与修正。不要把所有 AI 游戏统一限制成只有固定选项的文本包装。

给角色传入它能够获得的信息，区分世界事实与角色记忆。测试诱导泄密、把猜想写成既定事实、重复奖励、越界行动、记忆冲突和长局漂移。处理超时、取消、重试与离线回退；需要时以行动 ID 防止重复提交。记录实际延迟分布和单局成本，不把流式文字出现当成规则已经完成。

Generative Agents 论文研究可信的社会行为及记忆、反思和计划，亦报告边界错误；它不能直接证明一款游戏好玩、便宜或达到商业运行条件。[R03] 是否采用多 Agent，由可观察收益和复杂度决定。
