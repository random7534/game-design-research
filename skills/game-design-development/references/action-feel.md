# 动作手感：输入规则、动作承诺与反馈可读性

以下为公开资料支持的候选工作法。规格、例子与测试安排为本库综合，尚无本库玩家测试；来源及读取范围见 [sources.md](sources.md)。

按当前问题选择下面的方法。它们主要用于实时动作、平台跳跃和战斗；回合制、文字交互可借用状态与反馈检查，通常不需要逐帧窗口。

## 1. 为一个动作写出完整输入约定

按键被采样，只说明系统获得了事件；玩家想做什么还要由上下文解释。先逐项写清：触发事件是按下、松开还是持续按住；哪些状态允许执行；不允许时是保留、丢弃还是取消当前动作；保留多久；后来的指令能否替换；死亡、失去目标或打开菜单时如何清理。[F04]

建议交付一张表：`当前状态 × 输入 → 立即执行 / 保留至条件成立 / 拒绝 → 何时过期或替换 → 如何反馈`。双击和长按共用一个按钮时，补上意图尚不明确的阶段，以及先启动动作后修正是否允许。长按动作并非都必须等松开才响应。

验收时专门输入“落地前按跳”“攻击中按防御后改变主意”“按住按钮跨越状态切换”。分别检查漏输入、重复执行和过期执行。玩家说“没按出来”时，再查事件是否收到、是否因规则拒绝、是否仅在等待执行；这三种情况需要不同修改。

## 2. 把容错放在目标动作的边界

Celeste 作者的落地前缓冲例子要求在落地前短时间按下并保持跳跃键，不能由此推断松开也相同。先写想保留的挑战，例如选择起跳位置、判断落点或串联动作，再标记哪些失败来自边界误差。时间宽容和空间宽容应分别调：延长允许输入的时间，与移动角色绕过边角，会改变不同的可达范围。[F01]

本次建议用一对相邻情境检查每条辅助：一边是“略早或略晚，但仍符合目标动作”的输入；另一边是“玩家确实想停下、落下或选择另一动作”的输入。辅助既要减少前者的落空，也要检查是否替后者作了错误决定。不能只统计通关率。

若原本挑战就是精确节拍、空间边界或玩家之间的相互预测，扩大窗口会改变挑战内容。先决定哪些精度是作品要练习的能力，再决定哪些误差可以被吸收。节奏、竞技等类型需要分别验证，不把平台跳跃作者的选择自动推广过去。

## 3. 用取消关系说明强动作承担什么风险

把动作拆为起手、效果生效、收招三个阶段，逐项规定移动、下一招、防御、闪避能否提前结束当前动作。输入缓冲负责记住请求；取消窗口负责准许动作切换。二者可以组合，也可以分别限制。“部分/完整取消”描述指定转换的时间范围，“缓冲/立即执行”描述请求处理方式；完整取消不表示任意动作随时互转。[F02]

对“手感沉重”的反馈，先查玩家是否理解自己处于哪个阶段，以及此时有哪些合法回应。若高伤害大范围招可以随时无代价转防御，原有风险收益可能被改写；若基础动作长时间吞掉防御请求，玩家也可能难以建立可预测的操作习惯。

本次建议的规格字段：`阶段 / 可转入动作 / 命中或落空条件 / 资源消耗与退款 / 已排队动作如何处理`。检查两条实际序列：命中后取消是否反复制造无风险压制；落空后取消是否让所有强招都没有代价。取消越多并不自动越有深度，关键是改变了哪些可行策略。

自拟推演：玩家重击时补按下一次攻击，看到反击又按闪避。先入先出队列可能先执行旧攻击；开放任意取消又可能抹掉重击风险。应分别决定何时能转闪避、请求何时失效，以及闪避是否覆盖旧攻击，再核对实际输入和执行顺序。覆盖、清理和退款都由项目决定，原文没有统一队列算法。

## 4. 让反馈强度服从玩家要采取的行动

Riot 将信息层级与伤害、控制、可躲避性和对局影响联系起来，并举出预警形状暗示的可躲避性大于实际的反例。[F03]

本次建议给重要信号写四件事：它在说明什么、什么时候出现、玩家能做什么、何时已来不及。区分“输入已收到”“动作正在准备”“效果实际生效”“命中已确认”。只发生了前一件事时，不使用暗示后一件事已成立的提示。

在多目标同时出现的情境检查优先级，并记录哪项信息被粒子、镜头、声音或数字覆盖。装饰效果可以增加力度，但不能冒充新的危险范围或命中结果。新皮肤、新敌人变体和主题换皮要复核已学会的形状/声音含义。恐怖作品可以有意隐藏信息，但需要明确隐藏的是身份、时机还是结果，不能把无法判断的随机失败当成紧张感已成立。

按行为的重要性和频率分配动作与特效，连续普通操作不必反复启动大幅施法；对照同类原生行为，同时保留关键状态和兑现提示。效果意外变大时，分别核对源图像像素、纹理逻辑尺寸、节点或粒子缩放和屏幕范围，不能把高清源图直接当作显示尺寸。具体参数按宿主与用途核实，不把某个项目的图标尺寸套到所有游戏。

卡牌主题统一可以靠画风、材质和符号维持，不必每张都重复人物。按功能选择物件、动作或局部特写，用主体轮廓、方向、明暗及底色共同区分。把图放回实际卡框、裁切和手牌叠放尺寸检查；大图构图不同、文件校验通过，都不能代替小尺寸辨识。该做法来自一次卡图修订，最终手牌效果仍待实测，不作为已证实的辨识改善。

## 5. 用事件链定位手感问题，再安排对照

建议记录：`输入时间 → 当时状态 → 接受/保留/拒绝及原因 → 实际执行时间 → 判定结果 → 反馈出现时间`。这是综合 F01—F04 提出的排查方法，并非四篇文章共同验证过的标准流程。

同一投诉可能对应不同问题：输入未被采样、规则不允许、指令已过期、动画未表达准备阶段、碰撞结果和外观不一致。先根据事件链定位，再选择一次只调整一种因素的短实验。例如固定关卡和动作参数，只改变缓冲有效期；或者固定规则，只调整危险提示。记录成功、误触、过期执行、危险辨认与玩家原因复述，避免仅凭“更爽”决定扩大效果。

F04 引用了 F02，两文对取消的共同论述不能计作独立验证。资料没有给出通用最佳窗口；本库后续项目已有定向原生表现记录，仍缺玩家效果验证。可继续研究的缺口包括触屏手势、网络预测与命中确认、运动模拟惯性，以及不同无障碍需求下的输入方案；当前资料不足以制定这些类型的详细规范。
