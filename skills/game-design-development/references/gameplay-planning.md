# 玩法策划怎样做出可推演的方案

这里处理玩家的行动、判断、表达与变化。内容为依据公开来源形成的候选工作法；实际效果须在具体作品中检验。来源的直接主张和边界见 [sources.md](sources.md)。

## 从想法中找出可以玩的部分

从用户给出的题材或愿望出发，写出玩家扮演谁、操作什么、怎样影响世界，以及当下在乎什么。“经营海上旅馆”还需决定玩家主要是在安排房间、辨认旅客、组织航线，还是处理人际关系。选择这些动作会得到不同作品，不能用商店、宠物、装备等共同功能替代这项决定。

比较创意时，优先展示机制差异。可以固定题材换玩家动作，也可以固定动作换约束；这样才知道方案的差异来自哪里。限制只在能创造目标体验时保留。可行性作为选择条件，不能因此把所有创意降成同一种点击收集。

最短的玩法描述应能接着演示实际过程。若只能说“探索、收集、升级”，继续补充探索中发现什么、带走什么、为什么需要选择，以及升级以后能做出什么不同的行为。

Nintendo 的 Wonder 访谈提供了用机制原型筛选惊喜的案例。可以比较同一场景的不同规则变化，观察触发后玩家能否感到新意、理解发生了什么；惊喜本身可以是目标，不必再补策略成长。[G01]

## 动作、规则、反馈与下一步

| 层次 | 要写清什么 | 诊断问题 |
|---|---|---|
| 动作 | 瞄准、拖动、组合、盘问、布置等具体输入与对象 | 玩家在忙什么，操作本身是否值得做 |
| 规则 | 可行条件、作用关系、时序、成本和后果 | 系统怎样回应，玩家能否形成理解 |
| 决策 | 信息、备选办法、预期与牺牲 | 为什么此时选它，条件变化后会不会换办法 |
| 反馈 | 即时感知、原因说明、状态或角色回应 | 玩家知道发生什么、能否修正下一步 |
| 变化 | 新信息、局势、能力、关系或理解 | 下一步为何与刚才不同 |

用 MDA 把规则、运行行为和体验串起来，而非直接从题材推断乐趣。[D01] 游戏可能偏向操作熟练、规划、表达、感官享受或社交；不要求每次输入都产生一道策略难题。[D02]

## 玩法循环与继续玩的动力

玩法循环是反复出现的行动及结果。把它写成因果链，避免只画几个系统框。例如“听见求救 → 判断方向与风险 → 使用有限工具接近 → 救出旅客或改变航路 → 新局势下再次判断”。标出每次结果保留了什么，以及下一次哪些条件变化。

分清一次动作、一段挑战、一局和多局之间的关系。它们可以共享规则，也可只存在其中一部分。多局成长、日常任务和长期收集并非必需；一次完成的短作可以依靠完整情感或发现过程成立。

动机需要结合行动原因观察。操作次数、当时体验、继续意愿和实际回访分别记录；短篇、表达或放松作品也可以追求满意地结束。详见 [动机与奖励](motivation-rewards.md)。

继续玩的理由可能是提高操作、发现组合、解决新问题、探索未知、表达选择、创造作品或与人相处。逐个落实到具体过程，不把这些词直接当结论。若每轮只是相同操作换更大数字，要检查新增数字是否改变判断、节奏或可做的事；刻意追求稳定重复与放松时，则检查这种重复是否仍舒适。

## 决策怎样形成取舍

对重要选择写清玩家已知与未知的信息、可用办法、付出、收益、风险和延迟后果。既看数值，也看位置、时间、注意力、执行难度、承诺和情绪。表达性选择可通过自然回应和自我理解产生价值，不强制改变输赢。[D02]

有期限与人员占用时，将截止前完成机会、历时、人手、即时现金和被放弃的任务分别比较；随机期望不能当作当下可支付的余额。行动成功后再推演一次，检查历史是否改变下一轮可用办法。具体例子见 [案例方法 C19—C20](case-derived-planning.md)。

策略型作品检查某个办法是否在所有重要情境都更好。先改变局势检验适用条件，再决定调系数、增加反制或删掉冗余选项。加入冷却或价格可以限制强招，但也可能只增加等待；要说明它创造什么判断。

随机可能发生在决策前，给玩家一个需要应对的局势；也可能发生在行动后，给已作出的选择增加结果风险。两者对可规划性和责任感的影响需要分别观察。公平、惊喜和未知各有用途，不默认全部公开或全部隐藏。该区分为本库分析工具，非单篇来源已经验证的普遍效果。

对抗玩法还要检查：“知道对方会这样做以后，我能怎么办？”为强行动记录有效条件、可识别迹象、回应及代价，再检查变招会露出什么弱点。Sirlin 讨论的是竞争中的可行选项，不要求局部局势和终局始终有对等反制；此前互动形成优势后，关注胜负已定的阶段是否拖得过长。[G04]

## 机制组合怎样产生深度

把机制看成会互相改变用途的规则。举例：推箱子挡路、箱子能导电、电路能开门，三条规则组合后可以产生“移动障碍”和“接通电路”的不同计划。例子是虚构规则，并非某个已研究作品的事实。

检验组合时具体演示规则 A 怎样改变规则 B 的信息、目标、路径、时机、成本或结果；再演示条件变化后是否出现另一种用法。只有共同出现在菜单里，还不足以证明机制间存在互动。

同时计算代价触发的收益；“消耗”可能改善循环或启动另一种奖励。对首次、复制、自动执行等效果写清对象与生效时点。生产改动沿前置、设施、材料、工作与储存查影响范围；详见 [案例方法 C21—C22](case-derived-planning.md)。

Rosewater 提供的协同设计办法是先建立机制需求，再提供不同解法，让构件跨需求复用。[G03] 可以列一个很小的“构件 × 情境”表，发现新用途、重复功能与无用组合。谜题可从期望的一步巧思逆推条件；开放组合玩法则要检查是否被固定配方限制了其他合理办法。

复杂度是需要记忆、学习和操作的负担，深度是掌握规则后仍能发现的选择、技巧与应对空间。用这个区分比较方案，而非数机制数量。它是工作定义，不是统一量化标准。优先寻找少量可理解规则的多种用途，同时保留作品需要的丰富表达；不把“机制越少越好”当定律。

进一步借用 Rosewater 的分类，分别观察能否读懂规则、能否跟踪当前局面、理解后能否灵活运用。[G02] 简短规则大量互相影响，也可能造成很高的跟踪负担。先检查没有贡献的记账与例外；不把 Magic 的稀有度方案直接搬进其他游戏。

数值关系、资源转换与循环检查见 [systems-narrative-ai.md](systems-narrative-ai.md)。平衡目标要服从玩法：竞技需要可反制与适当公平，单人组合玩法可以有强力时刻；强弱差异本身不等同设计失败。[D03][D04]

## 挑战、关卡与变化怎样展开

为已有机制设计新问题，可以改变空间、目标、信息、对手行为、工具组合、时间安排或玩家身份。每项新内容要说明它改变了哪种行动与判断。敌人换颜色或数值也可能服务识别和节奏，只需不要把这种变化误写成新策略。

教学先让玩家注意并尝试，再用反馈形成理解，随后在变化情境中独立使用。[D05] 是否按引入、练习、组合和检验排列，由作品结构决定。分别定位操作要求、信息负荷、计划跨度，以及失败以后需要重复什么；定位后再改，不能笼统地用更多敌人代表一切难度。具体的谜题生成、通关/知识/线索关系和教学用途见 [关卡设计](level-design.md)；检查点与重试负担见 [原型与失败成本](prototype-and-challenge.md)。

节奏记录压力、信息、新鲜感与恢复机会的时间分布。L4D 的演讲提供区分威胁强度与出现节奏的具体案例，不能照搬其阈值或默认加入自动导演。[D08] 沉思、解谜和短叙事可以有不同曲线。

## 奖励、成长与重复游玩

先写奖励鼓励什么行为，以及它提供的信息、开放的用途和可能的压力。奖励可以确认熟练、允许新做法、揭示内容、改变关系或保存玩家创作。关闭奖励也可能同时移除进度反馈，不能据此直接判定内外动机。关注奖励是否意外鼓励最无聊的重复、囤积不用或跳过体验；用实际行为检验，不能只按设计者意图判断。

成长可提升效率，也可扩大动作、组合、路线与表达。记录新增能力会怎样改变已有问题，检查旧办法是否仍有用途。只加数值可以服务爽感与进度感，其是否足够取决于目标体验。

重复可玩性可以来自不同初始条件、互相影响的系统、技术提升、不同立场、玩家创造或社交。随机生成和内容数量只是可能的手段。演示同一组规则在不同情境中的过程，并观察是否真的引起不同选择或体验。

## 怎样判断一个玩法方案是否够具体

让另一人依靠规则走一小段，遇到歧义就记录。方案阶段至少能展示一个代表过程；涉及多次决策或重复游玩时，再展示局势变化后的过程。纸面推演用于查规则和选择，动作手感、操作节奏或空间感需要相应的交互原型。

每一步核对当前位置、行动额度、已拿材料、当前信息和可用能力。写“此时也能做另一种合成”之前，确认材料与前置条件齐全；这能区分真实可选办法与尚未成立的叙事设想。小表或口头核对足够，不为纸面方案另建技术架构。

原型的简化不能删掉决定待测体验的变量；声音辨位需要相应声音与空间条件，机制协同需要同时运行。可参考 [原型保留范围](prototype-and-challenge.md)。

本轮试玩只选择最关键的设计问题，例如“是否看懂风险”“是否会改变策略”“是否在乎表达”“是否主动尝试第二种组合”。记录失败条件、真实观察和下一次修改。用户只要求策划时，可以交付规则、推演和试玩设计；用户要求制作时再按范围实现。

方案按需用 [玩法设计简表](../assets/templates/game-brief.md)。重要判断须能落到具体动作和条件，不把“有策略性”“有爽感”“可玩性强”当成自身的证明。
