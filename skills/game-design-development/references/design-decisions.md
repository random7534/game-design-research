# 体验、规则与反馈怎样互相约束

本文件是依据来源形成的操作建议。来源主张见 [sources.md](sources.md)，其中 MDA、技能原子、叙事选择和 Valve 案例各有不同适用范围。

## 体验目标要能够改变设计选择

写“让玩家感到紧张”还不能决定规则。继续说明紧张来自时间、信息不全、损失风险、操作压力还是人际冲突。再写玩家能采取的应对方式。如果玩家无法预测任何后果，也无法改善应对，实际得到的可能是混乱或无力感；无力感也可以是作品目标，但需有意选择。

MDA 将设计拆为机制（规则与构件）、动态（规则运行时出现的行为）、体验（玩家感受）。用它检查推理链：某条机制为什么会诱发某种行为，该行为为何服务于体验。它是一种分析框架，不会自动产生好玩法，也没有要求作品包含固定数量的体验类别。[D01]

| 当前发现 | 优先检查 | 有区分度的下一步 |
|---|---|---|
| 玩家不知道做什么 | 目标是否可感知、行动是否可发现 | 让新玩家独立开始，记录第一次停顿 |
| 玩家理解却不愿行动 | 动机、表达价值、成本、预期回报 | 追问放弃原因，对照玩家实际行为 |
| 总选同一招 | 支配策略、情境变化、操作负担 | 构造不同局势，比较策略的机会成本 |
| 成功但不知道为何成功 | 因果反馈、信息显示、随机解释 | 请玩家复述刚才的原因，随后给新情境 |
| 明白规则仍觉得累 | 输入成本、重复、等待、认知负荷 | 去掉一项负担再比较，不直接追加奖励 |
| 总是很紧张却逐渐麻木 | 节奏缺少恢复段，或难度失控 | 固定敌人强度，单独调整威胁出现时机 |

## 一个选择有什么价值

分别考虑策略价值、操作表现、叙事后果、角色表达、情绪体验和社交承诺。不要求每个按钮同时承担所有价值。叙事选择即使回到同一情节，也可能改变角色的表达或玩家对事件的理解；需让选择含义和后续表达一致。[D02]

策略决策写清信息、可行选项、成本或风险和延后后果。检查选择前的信息能否支持判断，不同选项会不会在某些情境下交换优劣，玩家学到的东西能否用于下一次。纯装饰性选择可以存在，但不能承诺系统不会兑现的重大结果。

对放松、叙事、沙盒和无障碍模式，不机械增加惩罚或稀缺。对竞技、排行或付费资源，规则的一致性、可解释性和防重复结算通常有更高要求。

## 教学是把能力交给玩家

先写玩家需要掌握的动作、判断与前置知识，再安排可以注意到提示、尝试、看见反馈和迁移使用的情境。技能原子提供了拆解学习过程的视角；不要把“学习解释了某些乐趣”扩展成所有作品的唯一乐趣来源。[D05]

关卡可以按引入、练习、变化、组合和检验组织，但这只是一种安排。线性谜题适合精确控制信息；开放世界要考虑从不同入口进入的玩家。避免在失败后的第二次尝试仍强迫玩家重看已理解的长演出。提示应帮助定位问题或补足信息，是否给出解法由体验目标决定。

## 手感、节奏与叙事

输入反馈、命中或选择确认、声音、停顿与镜头共同影响玩家如何理解动作。明确规则效果和表现效果，避免震屏、粒子或音效掩盖危险信息。可访问性选项应保留可读反馈，不把同一种强刺激设为唯一通道。

Valve 的案例提供两类不同证据：Portal 用试玩持续调整谜题与叙事呈现；Left 4 Dead 的导演系统尝试调整强度节奏。两者都是特定项目的办法，不构成所有叙事都要少对白或所有游戏都要动态难度的要求。[D07][D08]

设计复盘保留一个因果链：改了哪个规则或呈现 → 玩家行为怎样变化 → 对体验的解释 → 仍有哪种替代解释。只记“玩家说挺好玩”不足以决定下一轮工作。
