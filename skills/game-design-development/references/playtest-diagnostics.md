# 测试要回答一个具体问题

先确定要做哪项决定，再选择观察。一个小样本可以暴露问题或推翻某个假设，通常不能估计整个市场比例。自动玩家、作者自测、朋友反馈和目标玩家各自能提供不同证据，不能互相替代。

## 准备一轮有用的试玩

记录版本、设备与输入、参与者与目标玩家的关系、任务、是否得到帮助、观察方法和本轮判断标准。数据或工程仍在并行变化时，固定本轮实际使用的输入快照及结果，不能只引用同名文件的旧通过记录。判断标准应在看结果前写下，并可根据探索性质说明其为暂定。

让玩家尽可能自己开始。观察卡住位置、误解、重复操作、成功归因、放弃和自发策略；适当询问原因，避免在玩家操作时不断讲解或诱导回答。出声思考可能改变节奏与表现，动作或沉浸体验可结合录屏与事后回顾。征得必要同意后才记录个人信息，不为小型试玩建立不必要的追踪系统。Portal 提供的是用测试迭代的项目案例，具体实验安排仍由当前问题决定。[D07]

根据项目选少量指标：目标理解、关键动作可发现性、达成任务所需帮助、失败能否解释、策略差异、情绪变化、完成或退出原因、愿否继续，以及对应原话。完玩率、复玩率、付费意愿和收入分别回答不同问题，不能用点赞、愿望单或某个满意分数替代全部结论。

## 对齐问题与观察

- 卡关：分别查发现、理解、推断、记忆、执行和重试负担，再决定是否改提示、输入或检查点，见 [关卡诊断](level-design.md)。
- 手感：记录输入、当时状态、接受/保留/拒绝、执行、判定与反馈时间，防止把过期指令误当设备慢，见 [动作手感](action-feel.md)。
- 动机：分别记行为、体验、继续意愿和实际回访。操作增加时仍可能更有压力，口头愿望还不是回访证据，见 [动机与奖励](motivation-rewards.md)。
- 遭遇：核对目标、敌人职责、实际危险重叠与波次边界，不能只数敌人或攻击名额，见 [战斗遭遇](combat-encounters.md)。
- 合作：以玩家组合观察协商、判断权、等待与互助；分别问每个人，处理组内和重复局次相关性，见 [多人协作](cooperative-play.md)。
- 成长：区分早中后期切片、加速规则推演和真实连续过程；保存退出与再次进入证据，见 [长期成长](long-term-progression.md)。
- 原型：先核对必需变量有没有被占位方案删掉，见 [原型保留范围](prototype-and-challenge.md)。

同一谜题第二次已知答案，动作练习也会产生顺序效应。选不同参与者、等价问题或平衡先后次序时，说明各自限制；不把一次短对照称为普遍因果验证。

## 比较信息辅助与机制组合

叙事和谜题辅助需要先固定信息与基础工具，再判断操作差异。帮助找回已发现的材料与额外揭示真相会改变不同任务。分别观察定位负担、解释依据、主动核查和完成结果，不把更快或少重听直接当作更好。相同玩家重做同一案件会记住答案；换题或分组也各有难度、人群差异，应说明比较限制。见 [案例方法 C18](case-derived-planning.md)。

复用敌人、关卡或设施后，按实际可达的角色/能力、对手/任务和阶段组合选择验证场景。制作量减少不自动减少新交互的检查；等价场景可以共享证据，但先说明等价依据，不穷举无关组合。特殊资源、无敌或自动出牌条件下的流程测试不能证明正常平衡。

## 结果如何改变工作

| 证据 | 能支持什么 | 尚不能支持什么 |
|---|---|---|
| 静态检查或编译通过 | 特定语法、类型或构建约束满足 | 关键流程可通、好玩 |
| 规则与存档自动测试 | 被覆盖的状态转换满足断言 | 美术可读、手感和叙事体验 |
| 作者走通主线 | 该版本该路径可以执行 | 新玩家能独立完成 |
| 目标玩家试玩 | 特定参与者在该条件下的行为 | 市场规模、长期留存 |
| 目标设备测试 | 该设备、系统、配置上的观察 | 所有设备表现 |
| 导出文件或上传成功 | 产物存在或传输完成 | 可安装、审核通过、正式上线 |

技术指标异常时先核对单位及测量中的转换，再归因于游戏改动。本轮声音检查曾因双声道转单声道而误报峰值来源；交付声道峰值、显式下混及有损格式差异必须分列。文件可解码、滤波存在和人能辨认是不同结论。

自动试玩还须区分测试工具缺陷、策略遗漏与真实失败。等待多段效果完成、重查目标合法性，并让策略识别当前场景的关键规则；脚本超时或角色死亡不能单独成为调平衡的依据。记录实际到达的章节、终止原因及未覆盖分支，不把中途失败写成通关。

用日志区分：看到的事实 → 可能解释 → 改动 → 复测结果。几名玩家表现不同，先检查经验、输入、版本与任务条件；不要直接平均掉差异。改规则、提示或难度前说明目标，尽量让下一轮能判断究竟哪项改动起作用。紧急修复可以同时做多个改动，随后降低因果结论的强度。

## 按项目裁剪的失败路径

- 开始、退出、重试、读档；重要分支与结局或沙盒持续状态。
- 边界资源、非法行动、重复点击或提交、暂停与恢复、顺序冲突。
- 断网、超时、取消与恢复，仅适用于依赖外部服务的功能。
- 小屏文字、触控误触、键鼠或手柄、颜色与音效替代、运动效果。
- 目标平台加载、运行和生命周期，以及实际使用的存档升级路径。

没有测试能力时保留可运行产物、可复现步骤和待验证项，不能补写测试已完成。完成证据用 [release-evidence.md](../assets/templates/release-evidence.md)；一次研究或文档任务可只写文档验证。
