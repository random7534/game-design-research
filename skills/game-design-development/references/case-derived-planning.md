# 从案例分析提炼玩法方法

用于复盘已有作品、评审改造和把项目发现迁移到新玩法。下列 C18—C22 是本库综合的候选方法；案例观察、数值模型和策划提案各自能支持什么，见 [案例证据表](case-observations.json)。它们尚无跨项目玩家效果验证，也未登记为个人认可。

## 先确定证据支持到哪里

先找到版本、规则位置、具体行动与结果，再提炼方法。对话里的进度总结只能帮助定位；收到一条建议、在报告中采用它、得到另一位分析者赞同，都不增加独立证据。保留反例与尚未查到的条件。解释原作时，区分作者意图、实际实现、构造情境和真实玩家行为。

迁移时写清四项即可：原案例发生了什么；由此提出什么设计假设；什么条件下可能适用；怎样观察它是否成立。不要把某个项目的参数、人数或流程顺序变成通用要求。

## C18 · 辅助玩家找回信息，同时保留需要他完成的判断

《疑案追声》的分析提出了一个边界：帮助返回已经听过、自己记录的片段，与自动标明证词真假、关联和遗漏，改变的是不同工作。前者也未必有益，记录和切换本身可能增加负担。开发者另说明，自由切换叙事顺序需要让玩家先看到结果后仍有原因可查；这为检查调查动作提供了背景，不能证明某种笔记界面有效。[开发笔记上篇](https://www.gcores.com/articles/132393)、[下篇](https://www.gcores.com/articles/132391)。

先问当前乐趣要求玩家完成什么：记住位置、辨认声音、建立关系、排除假设，还是解释因果。再标出辅助工具替他完成了哪部分。已听见某人说话，只能先记为该人的陈述；界面不要无意将其升级成世界事实。

试玩应区分找错位置的重复、主动验证的重复和没有方向的重复。速度变快后，还要看玩家能否解释关键关系、是否主动提出下一个问题，以及是否认为判断由自己完成。比较辅助界面时保持两版其他基础能力一致；同人重玩同谜题会记住答案，需换题或调整分组，并记录题目难度差异。

自由调查作品还可以做发现顺序测试：先看结果、先跟一名角色、先横向核对同一时刻，分别检查是否仍能形成有依据的问题。强作者顺序作品不必追求所有顺序都成立。无障碍模式或用户主动选择的答案辅助，可以明确改变信息与挑战范围，不能用保护谜题为由拒绝必要支持。

## C19 · 在期限和人手约束下比较选择

《苏丹的游戏》的有限规则研究显示，增加投入的价值需要结合阈值、期限与其他任务评估。局部成功率或平均奖励只回答局部问题；模型中算得出的收益，不包含模型没有表示的关系、资格和剧情代价。

对于要在有限时间完成的目标，同时比较：期限内完成机会、占用多少人及多久、每次支出、失败损失、其他被放弃的任务，以及可否中途改派。人员回合和成功概率使用不同单位，先保留并列结果；只有在效用和替代任务明确时才做统一评分。

例如下面是独立的虚构模型：每次尝试占一回合、最多尝试两次，失败后可原条件重试且各次独立。方案甲一人执行，单次成功率 50%；乙两人执行，单次成功率 75%。两次内成功率分别为 75% 和 93.75%；成功即停时，期望人回合分别为 1.5 和 2.5。乙更可能赶上期限，但多占用人力。是否值得，取决于未完成代价与第二人原本能做什么。

这是比较方式的例子，数字不属于原作。若失败改变难度、人物离场、随机相关或事件可用次数有限，就重建状态树，不能继续套独立重试公式。对风险、时间、表达或剧情目标不同的玩家，可保留不同偏好的有效选择。[D03][D04]

## C20 · 检查行动之后，下一次还允许做什么

一项行动的后果可能同时包含奖励和资格变化。《苏丹的游戏》某条家宅仪式路径的分析发现，成功留下的角色痕迹会参与后续条件判断。它只支持相应路径的限制，不能推成所有任务都禁用该角色。

评审时将“当前可用办法 → 行动与结果 → 新增或失去的办法”写出一轮，再继续第二轮。检查成功、失败、放弃、换人和读档后的差异；按实际存在的路径选择，不凭空要求作品提供所有功能。线索已公开、承诺已作出、设施被占用，也可能改变后续选择。

这能发现暂时优选与长期重复策略的区别。可用办法变化有时造成有趣的轮换，有时只增加记忆负担或不可预见惩罚，需检查是否可感知、是否还有合理选择。结算顺序会影响哪条后续规则读到新状态。[R02]

## C21 · 计算组合后的实际代价，并定义触发时点

卡牌改造评审中，有方案把移除一张牌作为新能力的代价；已有构筑却可能从这种移除中获益。该评审据此放弃了一个候选，属于设计推演，尚无新机制实装或平衡测试。

对成本写出它同时触发的效果：损失什么、得到什么、腾出什么、打开什么后续组合。再比较当前局面和少量代表构筑。减少手牌、弃置、消耗生命、延后行动等，都可能在别的机制中成为收益；这也可能是预期乐趣，不能一发现协同就削弱。关注获得条件、可靠程度与是否长期挤掉其他办法。[G03][D03]

同时明确一次行动何时算发生：预览或实际提交、手动或自动执行、原卡或复制/生成卡、取消或完成、一次动作或多段效果。计数型能力还要说明触发自己的动作是否进入计数、何时清空。用几段合法过程对照，保证提示、玩家理解与裁定一致，不必为纯策划搭建通用事件框架。

多角色共用敌人或终结机制时，按“角色 × 对手 × 阶段”挑代表局面检查可行回应、强组合与硬封锁。覆盖表能暴露未检查的组合；不能因为几场样例可行就宣称所有组合平衡。

## C22 · 顺着约束链评估生产改动

《幻兽帕鲁》的局部解析把科技解锁、设施生产筛选、材料、工作条件和容器容量连接起来。某参数的含义必须沿实际引用确认；改科技、设施或单条配方，会触及不同范围。局部静态证据没有覆盖整套联机与运行流程。

从一个玩家目标画出实际链条：解锁条件 → 可使用设施 → 可用配方 → 输入材料 → 工作者与时间 → 存储或消费。只画该目标需要的部分，记录已证实与未知连接。随后写“改哪个字段 → 哪项限制改变 → 上下游受什么影响 → 玩家能多做或少做什么”。

区分库存、每单位时间产量和等待队列。提升一段速度后，观察瓶颈是否转向供料、运输、储存或需求；这些限制在原作中是否存在，需逐项确认。提高效率可以服务节奏和爽感，不需要硬解释成增加策略。[D04]

含订单的系统还应核对材料暂存、实际消耗、进度、取消和产出如何相接，再判断中断的实际代价。批量公式注明按每份还是整单取整，以及最低数量限制；例如虚构订单每份需 3、保留 80%、向下取整且至少 1、共 5 份，逐份计算得到 10，整单才取整得到 12。两者都可能是设计选择，推演须与实际规则一致。玩家方案必须满足材料、资格、容量等前置条件；仅有配方条目不说明当前就能生产。适用范围是确有生产依赖的游戏，不能给纯装饰建造强加资源经济。

## 怎样使用这些候选

从当前卡点选择一项，写出预期观察和会推翻判断的情况。保留规则正确性与体验判断的区别：一种方案算对了、执行通了，仍可能不好懂、不值得选或不好玩。新案例出现时更新适用条件；具体方法的采纳按 [知识采纳规则](knowledge-adoption.md) 处理。
