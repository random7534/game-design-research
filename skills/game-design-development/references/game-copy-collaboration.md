# 游戏文案协作

用于用户指定外部模型或协作渠道主写、改写游戏文案的任务。沿用用户选择的渠道与模型；本机入口、模型偏好和验证记录保存在本地配置，不写成所有项目的默认要求。

## 准备能作判断的材料

提取实际使用的原文，保留字符串 ID、占位符和富文本标签，并标明它出现在哪个界面、针对什么对象。提供玩家当时已知的信息、相邻文本、角色语气及实际长度或行数限制；有助于判断时附对应截图，不能用孤立短句代替使用场景。

把可核对的规则与表达分开：数值、目标、费用、触发、持续时间和结算时序，以及会改变选择的例外，都属于不能随意改写的事实。文案依赖前一步取得物品、付款分支或隐藏信息时，一并说明。没有真实布局资料就说明这一缺口，不让模型凭空宣称已适配界面。

只向指定渠道提供本次必要且获准共享的项目材料，不发送凭据或无关私密文件。用于改稿的资料不因此获得公开发布授权。

## 确认请求和材料实际到达

发送前核实实际模型标识和当前渠道能力。图片须通过该渠道真实支持的附件或文件读取方式送达，并核对实际读取结果；不能假定非交互接口支持图片，也不能把只提供了路径称作模型已看过截图。

保留请求、完整返回稿和必要的模型或会话来源。已登录、模型能列出、进程退出码为 0，都不能单独证明改稿成功；正文为空或使用量为 0 时，继续核对诊断与实际返回内容。返回计划、提纲或审批请求时，仍需继续取得实际改稿。超时只代表当次未取得完整结果，不据此声称生成完成。

指定模型不可用时，保存材料并如实报告当前缺口，不虚构外部生成来源，也不静默换模型。重试应针对已查明的问题，避免反复提交同一份未完成请求。

## 取回后以返回稿为主

按字符串 ID 对照原稿与推荐稿，核对规则事实、术语、占位符和标签。简短表达仍须完整传达当前决策需要的信息，必要的失败原因和例外不能为缩字数删除。

事实、规则、逻辑或文体有实质问题时，把具体位置、依据和修改目标交回该模型修订。助手可校正错别字、链接及排版，不另写一遍整段或整稿替换协作者的表达。原稿、返回稿与应用差异留在开发记录，玩家界面不展示模型来源、改稿过程和检查备注。

## 直接改文件与应用

用户已授权直接改游戏文案时，先明确可改文件或字段，并与其他会话确认文件归属；不据此扩大到规则、资产或存档改动。优先使用专用副本或字符串替换表；直接进入工程也只修改约定范围，避免并发覆盖。

查清文本真正的生成源。生成器、源数据与必要镜像应按项目流程同步，不能只改一份下次构建就会被覆盖的生成文件。应用前后核对差异，保留可恢复版本。

在实际界面检查截断、换行、状态值替换与关键交互。静态文本检查只说明对应项已核对，不能代替真实显示或玩家理解测试；按本次修改的风险选择必要验证，不为小改动扩张测试范围。
