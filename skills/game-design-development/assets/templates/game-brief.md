# 玩法设计简表

按项目填必要项，未知项注明假设；不适用的项可删。此表是设计文档，不直接充当游戏界面文案。需要展示技能、按钮或提示时，另写简短、准确的玩家版；设计依据、测试和实现备注留在文档中。

## 目标与当前任务

目标玩家与游玩情境 / 体验目标 / 题材怎样进入动作和规则 / 输入方式 / 本次要交付的策划或实现范围。

## 玩家怎样玩

面向不了解作品的读者，先用一两句交代类型、玩家身份、目标与关键动作，再展示一件具体体验。游戏名称或抽象乐趣词不能替代这些背景。

玩家身份与动机；关键动作和对象；当下目标；可见和未知信息；结果与反馈；适用的结束、退出或继续方式。

## 实际游玩过程

从进入到一个有代表性的结果，演示看到的信息、动作、裁定与变化。涉及循环或策略时，继续演示局势变化后玩家如何再选；叙事、创作和放松作品采用适合自己的过程。

逐步核对位置、行动额度、已有材料、信息与前置条件，未取得的构件不写成当下可用。

## 机制、变化与继续玩的理由

机制怎样互相改变用途；挑战、关卡、成长、奖励或随机项各增加什么变化；理解负担；可能的单一最优办法；是否还需要长期循环及依据。

## 最小可验证范围

保留哪些动作和规则；删去哪些不影响本轮假设的内容；最危险假设与推翻条件。不要只列功能数量。

## 本轮验证

验证形式、参与者、预定判断标准、版本、观察、决定与下一步。纸面可验证内容与必须交互验证的手感、节奏或空间关系分开；尚未执行时写为计划。
